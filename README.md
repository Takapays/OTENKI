# 縦走山行判断ツール V1.7.4

## V1.7.4
- 初期表示は山未選択に変更。山を選ぶまでルート候補読込ボタンを無効化。
- 前地点の日時変更時、次地点を自動で「前地点 + 1時間」に設定。
- 前地点が宿泊なら、次地点を翌朝 5:00 に自動設定。
- CAPE の画面表記を「大気不安定度」に変更（値は J/kg）。
- 雷リスク HIGH / EXTREME を雷アイコンと警告色で強調。



## V1.7.4
- グラフ上に風速・突風・降水量・気温・雲量の数値ラベルを直接表示。
- 宿泊カードに「到着時気温（4モデル集計）」と「翌朝最低気温（0:00〜8:00）」を追加。
- 従来の夜間最低気温・最低体感なども継続表示。


## V1.7.4
- 縦走気象グラフを横幅内に収まるダッシュボード型に再設計。
- 「風」と「降水量」を1枚の複合グラフに統合。
- グラフ下にポイント番号対応の凡例を追加し、地点名が見やすくなるよう改善。
- カード・凡例・KPIチップを追加して全体デザインを強化。

## V1.7.4

- 通過地点だけでなく、宿泊地点の夜間分析も Open-Meteo が HTTP 429 の場合は MET Norway Locationforecast へ自動切替。
- 予備モードでも、夜間最低気温・体感温度の目安・風・突風・降水・雲量・ガスリスク・天の川スコアを継続表示。
- 日の入り・日の出時刻は地点の緯度経度から端末側で概算し、雲量・降水・湿度から見えやすさを判定。
- 宿泊カードに `MET Norway（予備）` / `Open-Meteo` の取得元を表示。
- MET Norway の時刻表示は日本時間（Asia/Tokyo）へ変換。
- Open-Meteoのモデル別・全地点一括取得、15分キャッシュ、429再試行は継続。
- 画面・JavaScript・サーバーのバージョン表示を V1.7.4 に統一。

## V1.6.3

- Open-Meteo 4モデルを同時発射せず、順番に取得して HTTP 429 を起こしにくくしました。
- サーバー側でも Open-Meteo 呼び出しを直列化し、短い間隔を空けてアクセスします。
- HTTP 429 時は Retry-After / 短い指数バックオフで自動再試行します。
- 成功した予報レスポンスのキャッシュを15分に延長し、同じ地点・日時の再分析でAPIアクセスを削減します。
- 画面、JavaScript、サーバーのバージョン表示を V1.6.3 に統一しました。


## V1.2

## Render
Build Command は以前のV5.5系のままでも動くよう `build_trail_graphs.py` を残していますが、V1.0では登山道データを使いません。推奨は:

`pip install -r requirements.txt`

Start Command:

`gunicorn --bind 0.0.0.0:$PORT --workers 2 --threads 4 --timeout 120 server:app`

## V1.7.4

- NOAA GFS 0.25° を NOAA/NCEP NOMADS の GRIB2 から直接取得する予備系を追加。Open-Meteo APIを経由しません。
- Open-MeteoがHTTP 429で利用できない場合、MET NorwayとNOAA GFS直取得を併用し、取得できた予報を結果比較に利用。
- NOAA GFSは約16日先までを対象とし、最新の利用可能なGFSサイクルを自動選択。
- GRIB2解析にECMWF ecCodes Python bindingsを使用。
