# 縦走山行判断ツール V1.6.5


## V1.6.5

- Open-Meteo が HTTP 429 のとき、約9日先まで MET Norway Locationforecast を予備APIとして自動利用。
- MET Norway利用時は4モデル比較ではなく単一予報として `FALLBACK` 表示。
- 宿泊詳細のOpen-Meteo取得だけが失敗しても、通過ポイントの気象分析結果は表示を継続。
- `api.met.no` 向けに識別用User-Agentを送信し、15分キャッシュを共用。

- Open-Meteoの取得を「地点ごと」から「モデルごとに全地点を一括取得」へ変更。
- 通常分析は最大で4モデル分のリクエストに圧縮し、地点数が増えてもAPI呼び出し回数が増えにくい構造に変更。
- 宿泊分析も宿泊地点を1回にまとめて取得。
- 標高が不足している地点がある場合も、標高APIをまとめて1回で取得。
- モデルの予報期間外の地点は、そのモデルだけ自動スキップ。
- ECMWFの利用目安を15日先までに統一。
- 画面・JavaScript・サーバーのバージョン表示を V1.6.5 に統一。

## V1.6.3

- Open-Meteo 4モデルを同時発射せず、順番に取得して HTTP 429 を起こしにくくしました。
- サーバー側でも Open-Meteo 呼び出しを直列化し、短い間隔を空けてアクセスします。
- HTTP 429 時は Retry-After / 短い指数バックオフで自動再試行します。
- 成功した予報レスポンスのキャッシュを15分に延長し、同じ地点・日時の再分析でAPIアクセスを削減します。
- 画面、JavaScript、サーバーのバージョン表示を V1.6.3 に統一しました。


## V1.2
- 登山道検索を廃止
- 距離・累積標高・コースタイム計算を廃止
- 「この山のルート候補を読み込む」は維持（内蔵候補を即時表示）
- 登山口・山小屋・・峠・山頂・下山口を手動選択
- 各地点の**通過日と通過時刻を手動入力**
- 「この計画を分析開始」で即気象分析

## Render
Build Command は以前のV5.5系のままでも動くよう `build_trail_graphs.py` を残していますが、V1.0では登山道データを使いません。推奨は:

`pip install -r requirements.txt`

Start Command:

`gunicorn --bind 0.0.0.0:$PORT --workers 2 --threads 4 --timeout 120 server:app`
