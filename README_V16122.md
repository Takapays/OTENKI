# V1.6.122 比較モデル不足時の日判定

- 121の日判定の閾値・時間別警告を維持。JMA/GFSの両方がそろう時間は従来の一致条件を適用し、片方しか取得できない時間は取得済みモデルで風・降水・低温の重なりを評価する。GEFSは既存の補助扱い。比較モデル不足だけでEを維持しない。
- 単独・短時間の危険は原則D。複合危険5時間以上、極端条件、雷・著しい視界不良はE。実際の気象値が不足して重大な危険を否定できない旧Eや外部安全補正は維持。Dは安全を意味しない。
- 原因別診断で比較モデル不足（旧判定）と気象値不足を区別し、モデル比較の不足座数を危険度と別に表示。詳細画面にも信頼度注意を表示する。
- 全国新規計算、既存キャッシュ読取時の再判定、詳細・Instagramで既存の共通サーバー関数を利用。キャッシュキー、エンジンv20、TTL、取得頻度、保存フィールド、Supabase/API読み書き関数、個別ルート判定に変更なし。実通信量は未計測。
- 適用: 差分ZIPの中身をリポジトリ直下に上書きし、通常どおりデプロイ。本体の122を確認した後、全国・Instagram Jobのイメージも122へ更新する。手動Job実行、キャッシュ削除、強制再取得は不要。共有キャッシュの通常表示で再評価される。端末の前回結果のみ表示する通信失敗時は旧判定が残る可能性あり。
- 検証: Python/JS構文、test_v16122_comparison.py（29基本ケース・3地上統合ケース、GEFS補助、旧キャッシュ、極端値、既存フィールド・サンプルJSONサイズ比較）、test_v16122_diagnostic.js。旧ZIPとの比較は環境変数 TRATEN_121_ZIP を指定。既存のテストは当時の期待値を維持した歴史的テスト。本番の全国分布・通信量は未確認。
