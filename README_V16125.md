# V1.6.125 全国マップ・詳細の同一予報スナップショット

## 124版で確認した構造上の問題
- 全国表示は共有キャッシュの判定を読み込み時に再評価する一方、山タップはMET/GFSを再取得し別世代の予報で日判定を上書きしていた。GFSのバッチと単独取得では採用サイクルが異なり得る。
- 確定済み日判定を保存済みの一部欠けた系列から再評価すると、同じ予報でも判定が変わり得る。現行の日判定済み行（122/125）はそのまま利用し、旧形式行だけ安全側の既存変換を1回実施する。
- MET欠測時にGFSに存在する気温まで捨てていた。MET主軸は維持し、標高補正が確認できるGFS気温だけ欠測時に補う。複合危険の判定閾値は変更しない。
- 詳細用にキャッシュから復元したJMAに日判定ラベルがなくても、保存済み時系列から日判定を算出する。主力上空風が取得できた際に古いGEFS補助を混用しない。

## 表示・運用
- 山をタップすると、マップに使った既存行で時間別表示を行う。追加気象取得・追加Supabase照会/書込なし。保存されていない個別モデルの時間別値は作らず、既存の保存済み危険根拠・統合値・上空風のみ表示する。
- 「この山の最新予報で再分析」で従来の詳細APIを明示的に実行し、取得後はバッジ・マップ・原因内訳・A〜E座数を同期する。MET/GFSを再取得し、利用可能なJMA保存データは従来どおり使用する。欠測値をゼロ扱いしない。
- 旧キャッシュの期限や既存のv20キー、Job周期、Supabase保存項目、meteoblue廃止、6/8/12時間TTLは維持。新規の統合気温に補完が入るが、保存項目を増やさない。GFSの標高補正フラグは取得時の内部系列にのみ追加。
- 既存124行で気温が欠けていても、保存されていない時間別温度を推測してEを下げない。通常更新で新判定へ移行。極端条件、複合危険、真の欠測・説明できない旧Eの安全側警告を維持。

## 配布
差分ZIPをリポジトリ直下へ上書き。本体と全国分析Jobを125へ更新。Instagram Job専用の変更はなし。キャッシュの全削除・強制更新は不要。

既存の日判定32ケース、TTL/JST境界（応答テストのスタブを新呼出に対応）、Cloud Run Job模擬、原因別診断21項目、新規スナップショット・気温補完・欠測・JMA復元テスト、Python/JS構文に合格。実際の光岳・聖岳の共有キャッシュと本番の気象入力は未取得のため、本番でのE数や判定変化は未確認。
